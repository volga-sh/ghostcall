<ManualSection index="02" title="Read two values" id="read-two-values">

This example reads the WETH total supply and one account balance on Ethereum.
ghostcall sends both reads in one RPC request.
It returns decoded `bigint` values in the same order.

```ts twoslash title="Listing 2.1 · TypeScript"
import { aggregateDecodedCalls } from "@volga-sh/evm-ghostcall";
import { erc20Abi } from "viem";

const token = "0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2";
const account = "0x28C6c06298d514Db089934071355E5743bf21d60";

const [supply, balance] = await aggregateDecodedCalls(client, [
	{
		to: token,
		abi: erc20Abi,
		functionName: "totalSupply",
	},
	{
		to: token,
		abi: erc20Abi,
		functionName: "balanceOf",
		args: [account],
	},
]);
```

</ManualSection>

<ManualSection index="03" title="Program operation" id="how-it-works">

A Multicall contract runs a batch of reads on the chain.
ghostcall uses contract creation to run a batch of reads without a Multicall contract.

If an `eth_call` has no `to` address, the EVM reads its `data` as initcode.
Initcode is the code that runs during contract creation.
It usually returns the runtime bytecode for the new contract.
The ghostcall initcode returns batch results.
The 60-byte program reads the call entries after its own bytes.
It runs the calls in order and returns one result entry for each call.

The `eth_call` only simulates these operations.
The chain does not keep a new contract or state changes.
