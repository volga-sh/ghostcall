<HomeSection title="Two reads. One request." id="read-two-values">

Describe the calls once and receive typed results in the same order. This example
reads the WETH total supply and an account balance on Ethereum.

```ts title="TypeScript"
import { aggregateDecodedCalls } from "@volga-sh/evm-ghostcall";
import { erc20Abi } from "viem";

const token = "0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2";
const account = "0x28C6c06298d514Db089934071355E5743bf21d60";

const [supply, balance] = await aggregateDecodedCalls(provider, [
  { to: token, abi: erc20Abi, functionName: "totalSupply" },
  { to: token, abi: erc20Abi, functionName: "balanceOf", args: [account] },
]);
// supply: bigint, balance: bigint
```

<HomeSection title="A small program, no deployment." id="how-it-works">

An `eth_call` without a `to` address runs contract creation code. ghostcall uses
that step to execute a 91-byte program: it calls each target in order and returns
the results. Everything happens in a simulation. No contract is deployed and no
state change is saved.

<HomeSection title="Before you send a batch." id="limits">

Your RPC endpoint must support CREATE-style `eth_call`. Request and response
size limits depend on the chain and provider, so test the endpoint your
application uses. `aggregateDecodedCalls()` throws if any call fails.
