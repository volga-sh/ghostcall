<ManualSection index="02" title="Read two values" id="read-two-values">

This example reads the WETH total supply and one account balance on Ethereum.
ghostcall sends both reads in one RPC request and returns decoded `bigint`
values in the same order.

```ts twoslash title="Listing 2.1 · TypeScript"
import { aggregateDecodedCalls } from "@volga-sh/evm-ghostcall";
import { erc20Abi } from "viem";

const token = "0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2";
const account = "0x28C6c06298d514Db089934071355E5743bf21d60";

const [supply, balance] = await aggregateDecodedCalls(client, [
	{
		to: token,
		abi: erc20Abi,
		functionName: "totalSupply",
	},
	{
		to: token,
		abi: erc20Abi,
		functionName: "balanceOf",
		args: [account],
	},
]);
```

</ManualSection>

<ManualSection index="03" title="How it works" id="how-it-works">

Batching reads normally means deploying a Multicall contract and routing every
read through it. ghostcall removes that dependency by using a step the EVM
already performs: contract creation.

If an `eth_call` has no `to` address, the EVM executes its `data` as initcode.
Initcode is the code that executes one time when a contract is created. The
initcode of a contract returns the runtime bytecode that the chain keeps.
ghostcall returns the batch results instead. Its 61-byte program reads the call
entries after its own bytes. It executes each call in order and returns one
packed result for each call.

Because `eth_call` only simulates execution, no contract is deployed and no state
change is saved.
